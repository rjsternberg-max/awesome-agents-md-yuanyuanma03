# 反模式：12 个最常见的坑

> 每条给出症状、为什么要命、怎么改。可配合 `amd check` 自动检测其中一部分（膨胀、含糊人设、整体转发、缺命令、缺边界）。

## 1. 文件膨胀

- **症状**：规则文件超过 500 行，塞满了 agent 本来就会做的事（"请写干净的代码"、"遵循最佳实践"）。
- **为什么要命**：每条规则都占上下文。ETH Zurich 实证：上下文文件使推理成本 +20–23%，冗余规则直接拖慢且稀释重要规则。
- **怎么改**：只写 agent 不知道的事。删掉所有"正确的废话"。

## 2. 含糊人设

- **症状**："You are a helpful coding assistant"、"你是一个资深工程师"。
- **为什么要命**：GitHub 对 2,500+ 仓库的分析显示这类话完全无效；有效的是具体角色定义（"测试工程师：只写测试，绝不修改源代码"）。
- **怎么改**：人设必须落到"做什么 / 不做什么"的可执行边界。

## 3. 整体转发（full indirection）

- **症状**：CLAUDE.md / AGENTS.md 里只有一句 "Strictly follow AGENTS.md" 或 "参见 AGENTS.md"。
- **为什么要命**：Hacker News 多人实测，agent 会随机忽略被转发的规则；间接引用的遵循率显著下降。
- **怎么改**：核心规则留在主文件；只对大块低频参考内容（架构、API 文档）做选择性引用。

## 4. 复读 README

- **症状**：规则文件大量复制 README 里的项目介绍。
- **为什么要命**：规则文件是**给 agent 的操作指令**，不是给人看的项目介绍；重复内容白花 token。ETH 研究还发现：LLM 生成的规则文件大多在复读已有文档，这正是它们轻微降低性能的原因。
- **怎么改**：写 README 里没有的东西——命令、边界、风格、完成标准。

## 5. LLM 一键生成、未经精修

- **症状****：用 `/init` 或让 agent 生成后就原样提交。
- **为什么要命**：实测 LLM 生成的上下文文件让解题率下降 0.5–2%。
- **怎么改**：生成的草稿只是起点，必须人工核对命令是否真实可跑、边界是否符合团队约定。

## 6. 没有完成标准

- **症状**：规则写了很多"怎么做"，没写"什么时候算做完"。
- **为什么要命**：agent 不知道何时停止，容易过度工程或提前交付。
- **怎么改**：写明可验证的完成条件（类型检查通过、测试通过、无新增警告）。

## 7. 规则里出现密钥

- **症状**：为了"让 agent 连接服务"，把 Token 写进规则文件并提交进 git。
- **为什么要命**：规则文件会被广泛共享（开源、多人克隆），等于泄露凭证。"Never commit secrets" 是所有实测仓库中最常见的有效约束。
- **怎么改**：凭证走环境变量或密钥管理；规则里只写"从哪里读环境变量"。

## 8. monorepo 只放根目录一份

- **症状**：多个包用不同技术栈（React 17 legacy 包 + React 18 新包），却只有根目录一份规则。
- **为什么要命**：一份规则无法同时匹配两套栈，agent 会用错版本写代码。
- **怎么改**：根目录放通用规则，各包目录再放各自的 AGENTS.md，就近原则自动生效（openai/codex 就是这么做的）。

## 9. 过度抽象的规则

- **症状**：要求 agent 使用某套"优雅架构"、"必须抽象出工具层"。
- **为什么要命**：诱导 agent 过度设计，为一次性需求创建抽象层。
- **怎么改**：规则约束结果而非架构；除非有真实复用场景，不要求抽象。

## 10. 死规则从不清理

- **症状**：只加不减，半年后文件里一半规则已过时（依赖已换、约定已改）。
- **为什么要命**：过时规则与新规则冲突时，agent 行为不可预测。
- **怎么改**：规则文件进版本控制，季度性回顾删除失效规则；改约定时同步删旧规则。

## 11. 没有边界（Never 清单缺失）

- **症状**：只有"要做什么"，没有"绝不能碰什么"。
- **为什么要命**：agent 不知道禁区，可能改动 `vendor/`、锁文件、生产配置等不该碰的东西。
- **怎么改**：用 ✅/⚠️/🚫 三级边界显式列出禁区。

## 12. 省略版本号

- **症状**："这是一个 React 项目"、"Python 项目"。
- **为什么要命**：不同版本写法差异巨大（React 16 class 组件 vs 18 hooks），agent 会拿训练数据里的旧写法来凑。
- **怎么改**：技术栈写到版本号——"React 18 + TypeScript 5 + Vite"。
