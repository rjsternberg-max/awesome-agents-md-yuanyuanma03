# 记忆系统模式：让 agent 记住发生过什么

> 规则文件（AGENTS.md / CLAUDE.md）回答"应该怎么做"；记忆系统回答"发生过什么"。两者结合才是完整的记忆。本页收录社区验证过的四种模式。

## 模式一：官方自动记忆（Codex Memories / CLAUDE.md memory）

Codex 在设置中开启记忆后，会自动把对话中的有效信息和关键偏好总结到 `~/.codex/memory/Memory.md`；Claude Code 有等价的 memory 机制。

- 适合：个人偏好类信息（常用语言、回答风格、常用路径）。
- 局限：自动总结不可控，需要定期人工审阅——删掉过时的、错的，保留真正稳定的。

## 模式二：CLAUDE.md 即大脑（自我改进循环）

来自 gmoneyNFT 的实践（[帖子](https://x.com/gmoneyNFT/status/2022454519741767800)）：

> "If Claude does something wrong twice, it goes in the CLAUDE.md."

每次纠正 agent 后，把教训固化成规则。配套 prompt：

```text
你刚才犯了和上次一样的错误。请：
1. 总结这次和上次的错误原因；
2. 把可复用的经验改写成一条规则，追加到 AGENTS.md 的对应章节；
3. 如果已有类似规则，修改它而不是新增。
```

Claude Code 作者团队的版本（[帖子](https://x.com/bcherny/status/2007179832300581177)）：共享一份 CLAUDE.md 提交进 git，全组每周多次修改——**记忆变成了团队资产而不是个人配置**。

## 模式三：双轨记忆（日志 + 精选）

```text
memory/
├── 2026-09-28.md   # 每日日志：当天做了什么决策、踩了什么坑
├── 2026-09-29.md
└── MEMORY.md       # 精选层：从日志里沉淀出的长期事实
```

- **每日日志**：会话结束前让 agent 自己总结写入（prompt 见下）。
- **精选层**：只保留稳定、长期有效的事实；agent 每次启动时读取。

配套 prompt：

```text
今天的会话结束前，请把以下内容写入 memory/$(date +%F).md：
- 今天做了哪些关键决策及原因
- 踩过的坑和解决办法
- 值得进入 MEMORY.md 的长期事实（如果有，同时更新 MEMORY.md）
```

## 模式四：按职责拆分的文件族

来自社区的分工方案（一个目录，各管一摊）：

| 文件 | 职责 | 示例内容 |
|---|---|---|
| `AGENTS.md` | 工作流规则 | 命令、边界、风格 |
| `SOUL.md` | 个性与语气 | "回答简洁、不铺垫、直接给结论" |
| `TOOLS.md` | 环境细节 | shell、路径、版本、别名 |
| `USER.md` | 用户上下文 | "我是全栈，偏好 TypeScript，讨厌过度设计" |

拆分的限度：见 [best-practices.md 第 9 条](best-practices.md)——核心规则留主文件，拆出去的是低频参考内容，不要整体转发。

## 选择建议

- **个人用户**：官方自动记忆（模式一）+ 第二次犯错触发加规则（模式二）就够了。
- **重度用户 / 多项目**：加上双轨记忆（模式三）。
- **团队**：把规则文件变成团队共享资产（模式二的团队版），记忆按人各自维护。
